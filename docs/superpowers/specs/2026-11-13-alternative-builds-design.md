# 분기 빌드(코어 A·B·C) 설계

2026-11-13 · 상태: 초안

## 1. 왜 만드는가

소우리는 "반격을 메인으로 아드레날린·숫돌 축을 가느냐, 반격은 서브로 두고 회복 축을 가느냐"를 두고 커뮤니티 연구와 우리 판정이 계속 뒤집혔다. 지금 규칙은 한쪽(회복 축)만 코어로 두고 다른 쪽(아드·숫돌)을 보류로 막는다. 그래서 의견이 바뀔 때마다 판정 전체를 뒤집어야 했다.

이 판정을 한쪽으로 고정하지 않는다. **두 빌드가 모두 성립한다고 보여 주고, 플레이어가 한쪽 칩을 집는 순간 다른 쪽을 보류로 바꾼다.** 소우리처럼 빌드가 갈리는 다른 캐릭터에도 같은 형식을 쓴다.

## 2. 목표 · 비목표 · 반목표

목표
- 캐릭터마다 빌드를 2~3개(A·B·C) 둘 수 있다. 빌드는 짧은 설명과 코어 칩 목록을 가진다.
- 갈림길 전에는 모든 빌드의 코어가 ★ 코어로 뜨고, 그 칩이 어느 빌드의 코어인지 글자 블럭으로 보인다.
- 어느 빌드의 코어 칩을 하나라도 가지면 그 빌드를 고른 것으로 본다. 고르지 않은 빌드의 코어 칩은 × 보류가 되고, 글자 블럭과 빌드 설명이 화면에서 사라진다.
- 칩 선택 창 제목 띠 오른쪽에 빌드 A·B·C의 짧은 설명을 보여 준다.
- 빌드가 없는 캐릭터의 화면과 판정은 지금과 똑같다.

비목표 (이번 작업에서 하지 않음)
- 소우리 빌드 내용 확정(아드 축에 넣을 표식·에너지 칩, C가 필요한지). 별도 작업에서 독립 분석·시뮬레이션·원문 대조 심판으로 정한다.
- 다른 캐릭터의 빌드 후보 찾기. 별도 작업.
- 맵·아군 조건에 따라 빌드 자체를 바꾸는 것. 빌드는 캐릭터 단위로만 둔다.
- 키워드가 막혀 한 빌드가 사실상 불가능해졌을 때 그 빌드를 자동으로 닫는 것. 나중에 검토한다.
- 칩을 얻은 순서로 빌드를 정하는 것. 가진 칩 집합만 본다.

반목표 (기술적으로 돌아가도 실패로 본다)
- 고르지 않은 빌드를 회색으로 남겨 두는 것. 사용자가 명시적으로 원하지 않았다. 블럭과 설명은 아예 뺀다.
- 빌드 이름을 배지 자체에 넣어 배지가 길어지는 것. 배지는 지금처럼 `★ 코어`이고, 빌드 정보는 배지 아래 글자 블럭으로만 보인다.
- 빌드가 갈리지 않는 캐릭터에 빌드를 남발해 ★가 쏟아지는 것.

## 3. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **rules.json 캐릭터 항목에 `builds` 추가** | 캐릭터 항목 안에 `builds: { A: {...}, B: {...} }`를 두고, 엔진이 가진 칩으로 고른 빌드를 계산한다 | **채택.** 데이터가 짧고, 화면에 필요한 "이 칩은 B 빌드" 정보가 규칙에 남는다 |
| 지금 형식의 보유 칩 조건 규칙으로 표현 | "B 코어를 가지면 A 코어 보류" 규칙을 칩 조합마다 쓴다 | 제외. 캐릭터가 늘면 규칙이 크게 불고 빠뜨리기 쉽다. 글자 블럭·빌드 설명에 쓸 정보가 없다 |
| 빌드만 담은 별도 파일 | `builds.json`을 따로 둔다 | 제외. 캐릭터 판정이 두 파일로 나뉘고 자동 교체·백업 처리만 늘어난다 |

표시 방식은 대화에서 정했다. 빌드 이름 대신 `코어 A·B·C`로 부르고, 빌드 설명은 제목 띠 오른쪽에, 빌드 글자는 배지 아래 세로 블럭으로 보여 준다.

## 4. 규칙 형식

```jsonc
"소우리": {
  "role": "dealer",
  "core": ["추가 배터리", "바이크 헬멧", "샌드 쿠키"],      // 공용 코어: 어느 빌드든 코어
  "good": [...], "avoid": [...], "why": {...},              // 지금과 같음
  "builds": {
    "A": {
      "label": "아드 반격",
      "core": ["아드레날린", "숫돌"],
      "good": [...],                                          // 선택. A를 고른 뒤에만 적용
      "avoid": [...],                                         // 선택. A를 고른 뒤에만 적용
      "why": { "숫돌": "..." }                                // 선택
    },
    "B": { "label": "힐 탱커", "core": ["완충 방패", "구급 상자"] }
  }
}
```

| 키 | 규칙 |
|---|---|
| `builds` | 객체. 키는 `A`, `B`, `C`만 허용. 2개 이상이어야 한다. 1개뿐이면 오류를 남기고 `builds` 전체를 무시한다 |
| `label` | 필수. 공백만 있으면 안 된다. 6자 안팎을 권장하고, 10자를 넘으면 오류를 남기고 그 빌드를 뺀다 |
| `core` | 필수. 이름 해석 뒤 하나 이상 남아야 한다. 남지 않으면 그 빌드를 뺀다 |
| `good` / `avoid` | 선택. 형식은 캐릭터 목록과 같다(문자열 또는 `{chip, why, minGrade}`) |
| `why` | 선택. 칩별 이유. 없으면 캐릭터 `why`, 그것도 없으면 `소우리 코어 A` 같은 기본 문구 |

- 같은 칩이 캐릭터 공용 `core`와 빌드 `core`에 함께 있으면 오류를 남기고 빌드 쪽에서 뺀다. 역할 공용 코어·조건부 코어와 겹치는 것은 오류로 보지 않는다(5-2의 "빌드와 상관없이 코어"가 처리한다).
- 같은 칩이 여러 빌드의 `core`에 있어도 된다. 이 칩은 그 빌드들 모두의 칩으로 표시되고, 가지면 그 빌드들을 모두 고른 것으로 본다.
- 빌드가 빠져 2개 미만이 남으면 `builds` 전체를 무시하고 오류를 남긴다.
- 오류 문구는 지금 형식을 따른다. 예: `characters.소우리.builds.D: A, B, C 중 하나여야 합니다`, `characters.소우리.builds.A.core[1]: '이름' 칩을 찾을 수 없습니다`.
- `version`은 1 그대로 둔다. `builds`를 모르는 이전 버전 플러그인은 이 키를 무시한다.

## 5. 판정

### 5-1. 고른 빌드

- 빌드는 **열림** 또는 **닫힘** 상태다.
- 가진 칩 중에 어떤 빌드의 `core` 칩이 있으면 그 빌드를 **고름**으로 본다. 등급은 따지지 않는다(지금 `owned` 조건과 같다).
- 고른 빌드가 하나도 없으면 모든 빌드가 열림이다.
- 고른 빌드가 있으면 고른 빌드만 열림이고 나머지는 닫힘이다. A와 B의 칩을 모두 가졌으면 A·B가 열림이고 C만 닫힘이다.

### 5-2. 칩 판정

1. 빌드 `core`는 캐릭터 단계(단계 2)의 코어 규칙이다. 빌드 표시를 위해 규칙에 빌드 글자를 달아 둔다.
2. 빌드 `good`/`avoid`도 단계 2지만, 그 빌드가 **고름** 상태일 때만 적용한다. 열려 있지만 아직 고르지 않은 빌드의 보류가 다른 빌드 코어를 미리 막지 않게 하려는 것이다.
3. 지금 방식대로 단계와 판정으로 최종 판정을 정한다. 지금 로직은 그대로다.
4. 그다음 **닫힌 빌드 덮어쓰기**를 적용한다. 칩이 닫힌 빌드의 `core`에 속하고, 열린 빌드의 `core`가 아니며, **빌드와 상관없이 코어**도 아니면 최종 판정을 × 보류로 바꾼다.
   - "빌드와 상관없이 코어"는 빌드 규칙(빌드 `core`/`good`/`avoid`)을 모두 빼고 판정했을 때 코어가 나오는 칩이다. 캐릭터 공용 `core`, 역할 공용 코어(딜러 공용 복싱 글러브 등), 빌드 밖의 조건부 코어(`{character:[소우리]}` 잉어 인형 등)가 여기에 든다. 빌드에 이런 칩을 넣어도 다른 빌드를 골랐다는 이유로 막히지 않는다. (빌더 판단)
   - 이유: `코어 A를 골라 보류 (B 힐 탱커 빌드 칩)`. 열린 빌드가 둘이면 `코어 A·B를 골라 보류 …`.
   - 원래 이긴 판정의 이유는 `참고:`로 내린다(최대 3줄 규칙 그대로).
   - 이 덮어쓰기는 단계와 무관하게 마지막에 적용한다. 빌드 밖 규칙(맵·아군 조건 포함)이 지금 상황에서 그 칩을 코어로 올리면 위의 "빌드와 상관없이 코어"에 해당해 덮어쓰지 않는다. 그 밖의 무난·보류 판정은 모두 보류로 바뀐다.

### 5-3. 엔진 출력

| 출력 | 내용 |
|---|---|
| `Advice.Builds` | **최종 판정이 ★ 코어일 때만**, 이 칩이 `core`에 든 열린 빌드의 글자 목록(A→C 순). 공용 코어 칩, 열린 빌드 코어가 아닌 칩, 최종 판정이 코어가 아닌 칩은 비어 있다. 닫힌 빌드 글자는 넣지 않는다. 예: 갈림길 전이라도 아군 루루 때문에 아드레날린이 × 보류면 글자 블럭이 없다. (빌더 판단: 글자 블럭은 "어느 빌드의 코어인지" 표시라 코어 배지 아래에만 둔다) |
| `ChipAdvisor.Builds(rules, situation)` | 제목 띠에 보여 줄 빌드 목록 `(글자, label)`. 빌드가 없는 캐릭터면 null, 갈림길 전이면 모든 빌드, 고른 뒤면 열린 빌드만. 빌드가 열리고 닫히는 것은 가진 칩으로만 정해진다. 다만 열린 빌드라도 지금 그 빌드의 코어가 아군·맵 조건으로 모두 보류이면 제목 띠에서 뺀다(2026-11-14 사용자 결정: 코어 줄과 말이 어긋나지 않게) |
| `ChipAdvisor.CoreChips` | 지금처럼 최종 판정이 코어인 칩. 코어 줄 글자 표시를 위해 칩마다 열린 빌드 글자를 함께 돌려준다 |

키워드 고정 경고가 쓰는 "막히는 코어 칩"도 최종 판정이 코어인 칩이다. 그래서 갈림길 전에는 다른 빌드 코어도 경고에 들어간다. 그 빌드도 아직 갈 수 있는 길이니 맞는 동작이다.

## 6. 화면

기준 화면은 칩 선택 창이다(README의 `docs/images/ui-guide.png`와 같은 배치).

### 6-1. 빌드 설명 (제목 띠 오른쪽)

```
갈림길 전   [A] 아드 반격   [B] 힐 탱커
고른 뒤     [A] 아드 반격
```

- 위치: "강화 칩을 선택해 주세요" 제목 띠 안쪽 오른쪽 끝. 띠 세로 가운데에 맞추고, 오른쪽 여백은 키워드 패널 여백과 같게 둔다. 게임의 표정·채팅 버튼 줄(`ExpressionWindow.com_Interact_PC`)이 띠 오른쪽 끝을 덮으므로, 띠와 세로로 겹치는 버튼이 있으면 그 버튼 왼쪽 끝을 오른쪽 끝으로 삼는다(2026-11-14 실기 확인: 1920 기준 x 1841부터 버튼). 띠 위치는 `KeywordPanel`이 쓰는 띠 탐색(`txt_Probability`를 가로지르는 넓은 자식)을 재사용한다.
- 내용: 빌드마다 글자 블럭(6-2와 같은 색)과 `label`. 열린 빌드만 보여 주고, 닫힌 빌드는 칸째 뺀다.
- 한 줄에 들어가지 않으면 두 줄로 쌓는다. 제목 글자 오른쪽 끝을 넘어가면 안 된다.
- 띠를 찾지 못하면 그리지 않는다. 키워드 패널은 띠가 없으면 확률 글자 위나 창 맨 위로 물러나지만, 빌드 설명은 띠 안쪽 오른쪽이라는 위치 자체에 의미가 있고 같은 정보가 글자 블럭으로도 보이므로 물러날 자리를 두지 않는다. `상세 로그`가 켜져 있으면 한 줄 남긴다. (빌더 판단)
- 2026-11-13 현재 클라이언트 화면(사용자 캡처)에서 이 자리는 비어 있다. 맵에 따라 띠 바로 위 오른쪽에 `단서 0/5` 같은 맵 표시가 있으나 띠 안쪽과는 겹치지 않는다.
- 글자 크기는 키워드 패널과 같은 값(제목 글자 × 0.6)을 쓴다.

### 6-2. 빌드 글자 블럭 (배지 아래)

```
숫돌        [★ 코어]
            [A]
완충 방패   [★ 코어]       → 숫돌을 가진 뒤   [× 보류]   (블럭 없음)
            [B]
추가 배터리 [★ 코어]       ← 공용 코어라 블럭 없음
```

- `Advice.Builds`의 글자마다 작은 정사각 블럭을 배지 아래에 세로로 쌓는다. 블럭 한 변은 배지 높이, 오른쪽 끝은 배지 오른쪽 끝에 맞춘다.
- 글자마다 색을 고정한다(A·B·C 세 색). 빌드 설명의 글자 블럭과 같은 색이다. 배지 색(코어 노랑, 무난 초록, 보류 빨강)과 구분되는 색을 쓴다.
- 블럭이 칩 설명 글자와 겹치면 안 된다. 세 칸이 들어가지 않는 카드 크기면 가로로 붙인다.

### 6-3. 툴팁

- 글자 블럭이 붙은 칩(`Advice.Builds`가 비어 있지 않은 칩): 첫 줄에 `코어 A (아드 반격)`, 그 아래 지금처럼 이유와 참고를 둔다. 글자 블럭이 없으면 이 줄도 없다.
- 닫힌 빌드 칩: 지금 보류처럼 이유 줄에 5-2의 문구가 나온다.

### 6-4. 코어 칩 줄 (확인 버튼 아래)

- 최종 판정이 코어인 칩을 지금처럼 보여 준다. 그래서 갈림길 전에는 모든 빌드 코어가, 고른 뒤에는 공용과 열린 빌드 코어만 남는다.
- 빌드 코어 아이콘의 오른쪽 아래에 작은 글자 블럭(6-2 색)을 붙인다. 공용 코어에는 붙이지 않는다.
- 순서: 공용 코어, A, B, C. 같은 그룹 안의 순서는 지금 순서를 따른다.

### 6-5. 설정

`BepInEx/config`의 `일반` 섹션에 `빌드 설명`(기본 켜짐)을 더한다. 끄면 6-1만 숨기고, 판정·글자 블럭·툴팁은 그대로다. `표시 전환 키`의 설명 문구에 빌드 설명을 더한다.

## 7. 시험용 데이터 (소우리)

빌드 기능을 확인하기 위한 첫 데이터다. 내용은 비목표에 적은 별도 작업에서 다시 정한다.

| 위치 | 칩 |
|---|---|
| 공용 `core` | 추가 배터리, 바이크 헬멧, 샌드 쿠키 |
| `builds.A` 아드 반격 `core` | 아드레날린, 숫돌 |
| `builds.B` 힐 탱커 `core` | 완충 방패, 구급 상자 |
| 캐릭터 `avoid`에서 뺄 것 | 아드레날린, 숫돌 (빌드 A 코어로 옮김) |
| 캐릭터 `good`에서 뺄 것 | 구급 상자 (빌드 B 코어로 옮김) |

이미 있는 일반 규칙("아드레날린 보유 → 완충 방패·회복 칩 보류")은 그대로 둔다. 빌드 덮어쓰기와 결과가 같아서 충돌하지 않는다.

## 8. 문서와 시험

- `docs/RULES.md`: `builds` 키, 검증 규칙, 오류 문구, 판정 순서 표에 "닫힌 빌드 덮어쓰기(마지막)"를 추가한다.
- `docs/RECOMMENDATION.md`: 1절 표시 표에 빌드 글자 블럭·빌드 설명, 2절에 덮어쓰기, 9절 소우리 행을 고친다.
- `README.md`: 화면 안내에 빌드 설명·글자 블럭을 추가한다. 이미지 교체는 실제 화면을 찍은 뒤에 한다.
- 시험(`tests/ChipGuide.Core.Tests`)
  - `RuleBookTests`: 키 검증(A~C 밖, 1개뿐, label 없음·10자 초과, core 비어 있음, 공용 코어 중복)과 오류 문구.
  - `ChipAdvisorTests`: 갈림길 전 모두 코어와 글자, 한쪽 보유 시 다른 쪽 보류·글자 없음·참고 줄, 양쪽 보유, 빌드 good/avoid는 고른 뒤에만, 빌드 밖 조건부 무난·보류가 걸려도 덮어쓰기가 이김, 빌드 밖 조건부 코어는 덮어쓰지 않음, 공용 코어 칩은 덮어쓰지 않음, `Builds()` 출력, 빌드 없는 캐릭터는 지금과 같음.
  - `ShippedRulesTests`: 소우리의 갈림길 전과 숫돌 보유 뒤, 완충 방패 보유 뒤.
  - `ShippedRulesTests`의 `모든_캐릭터는_코어가_넷_이상이고_코어_키워드는_두_종류를_넘지_않는다`: 빌드가 있는 캐릭터는 빌드마다 따로 검사한다. 빌드 하나의 코어 칩을 가진 상황(그 빌드만 열림)에서 코어가 넷 이상이고 코어 키워드가 두 종류 이하인지 본다. 빌드끼리는 키워드가 달라도 된다. 아드 축이 표식·에너지, 힐 축이 회복으로 갈리는 것이 이 기능의 핵심이라서다. (빌더 판단)

## 9. 제약

- 코드 주석은 사용자 전역 규칙을 따른다(복잡한 알고리즘·이해하기 어려운 이유만, "왜" 위주).
- 플러그인 화면은 IL2CPP FairyGUI 객체를 이름 기반으로 다룬다. 새 화면 요소도 `Ui`/`GameUi` 도우미와 `BadgeView.Clear()` 정리 경로를 쓰고, 실패하면 그 요소만 빠지고 나머지 표시는 유지해야 한다.
- 규칙은 id로 맞춘다(영문 클라이언트도 한국어 참조표로 이름을 찾음). `label`은 화면에 그대로 나오는 문구라 번역하지 않는다.
- PvE에서만 표시한다(지금 게이트 그대로).

## 10. 빌더에게 맡기는 것

- 글자 블럭 세 색의 정확한 값. 지금 배지 색과 구분되고 흰 글자가 읽히면 된다.
- 빌드 정보를 `RuleSet`에 담는 구체적 자료형과, 덮어쓰기를 `AdviseOne` 안에 넣을지 뒤에 둘지.
- 제목 띠 안에서 줄을 바꾸는 정확한 기준 폭.
- 진단 로그(`상세 로그`)에 고른 빌드를 한 항목 더하는 형식.
