# 규칙 작성 안내

## 출처

기본 `rules.json`의 추천 데이터는 Feiz님의 「캐릭터별 나왔을 때 집어가면 좋을 코어 칩 및 플레이 방법 가이드」(https://arca.live/b/astralparty/171581722)를 바탕으로 합니다. 작성자의 허락을 받아 사용했습니다.

공략에 없는 조합 일부는 칩 효과 설명과 캐릭터 스킬 설명으로 추정해 보강했습니다. 조건부 규칙은 `rules.json`의 `rules` 목록에서 "추정 규칙" 주석 아래에 모아 두었습니다. 캐릭터별 코어는 2026-10-17 재검토로 더한 칩이 공략 코어와 함께 `characters`에 들어 있고, 더한 칩은 [RECOMMENDATION.md 9절](RECOMMENDATION.md#9-캐릭터별-근거)에 적었습니다.

## 파일 위치

| 파일 | 위치 | 역할 |
|---|---|---|
| `rules.json` | `BepInEx\plugins\AstralPartyChipGuide\rules.json` | 추천 규칙. 직접 수정합니다. 모드 업데이트 때 새 기본 규칙으로 바뀝니다(아래). |
| `rules.json.bak` | 같은 폴더 | 업데이트로 바뀌기 전, 직접 고친 `rules.json`. 고친 적이 없으면 만들지 않습니다. |
| `names.json` | 같은 폴더 | 칩·캐릭터·맵 이름과 ID 대응표. 직접 만들지 않고 게임에서 생성합니다. |
| `names.ko.json` | 같은 폴더 | 기본 규칙이 쓰는 한국어 이름과 ID 대응표. 모드에 함께 들어 있고 직접 고치지 않습니다. |

기본 규칙은 같은 폴더의 `rules.default.json`에 들어 있습니다(직접 고치지 마세요). 게임을 켜면 `rules.json`이 없을 때 만들고, 모드를 업데이트해 기본 규칙이 바뀌었으면 새 기본 규칙으로 바꿉니다. 첫 줄의 `// 칩 가이드 v… 기본 규칙 […]`이 그 판단에 쓰는 표시입니다.

- 기본 규칙이 그대로인 업데이트에서는 직접 고친 내용을 건드리지 않습니다.
- 기본 규칙이 바뀐 업데이트에서는 직접 고친 파일을 `rules.json.bak`으로 옮기고 새 기본 규칙을 씁니다. 고친 내용이 필요하면 새 파일에 다시 옮기세요.
- 첫 줄을 지우면 다음 실행 때 새 기본 규칙으로 바뀝니다(고친 파일은 `.bak`에 남습니다).
- 파일을 바꾸지 못하면(읽기 전용 등) 그 실행 동안은 DLL에 든 기본 규칙을 씁니다.

`names.json`이 없으면 규칙을 읽지 못합니다. 게임을 켜고 로비에 들어가면 같은 폴더에 자동으로 만들어지고, 실행할 때마다 게임 데이터와 비교해 바뀐 것이 있을 때만 다시 씁니다. 그래서 게임 업데이트나 언어 변경도 다음 실행 때 반영됩니다. 파일에는 게임의 칩·캐릭터·맵 테이블만 들어가며 계정 정보는 들어가지 않습니다.

규칙의 이름은 먼저 `names.json`(지금 게임 언어)에서 찾고, 없으면 `names.ko.json`에서 같은 ID를 찾습니다. 그래서 한글 패치가 게임 업데이트를 아직 따라오지 못해 게임이 영어로 나와도, 한글 패치가 신규 칩을 다른 이름으로 번역해도 기본 규칙이 그대로 동작합니다. 직접 고칠 때는 지금 게임에 보이는 이름이나 `names.ko.json`의 이름 어느 쪽을 써도 됩니다.

## 형식

`rules.json`은 주석(`//`)과 마지막 쉼표를 허용합니다. 칩·캐릭터·맵은 게임에 표시되는 이름으로 씁니다. 파일 크기는 1MB까지, 이유 문구는 200자까지입니다.

```jsonc
{
  "version": 1,
  "roles": {
    "common":  { "good": ["추가 배터리"] },
    "dealer":  { "good": ["복싱 글러브"] },
    "support": { "good": ["돼지 저금통"] }
  },
  "characters": {
    "미미": {
      "role": "support",
      "core":  ["대형 배낭", { "chip": "휴대용 선풍기", "minGrade": "purple" }],
      "avoid": [{ "chip": "복싱 글러브", "why": "서포터는 코인 배분이 우선" }],
      "why":   { "대형 배낭": "스킬로 패를 갈수록 코인 이득" }
    }
  },
  "rules": [
    { "when": { "owned": ["아드레날린"] }, "chip": "커터칼", "verdict": "core", "why": "아드레날린과 함께 쓰는 칩" },
    { "when": { "ally": ["루루", "판다맨"] }, "chip": "아드레날린", "verdict": "avoid", "why": "아군 회복이 아드레날린 조건을 깸" }
  ]
}
```

| 키 | 설명 |
|---|---|
| `version` | 반드시 `1` |
| `roles` | 포지션별 공용 추천. `common`(모두), `dealer`, `support`, `skill`. 각각 `core`/`good`/`avoid` 목록을 가집니다. |
| `characters` | 캐릭터별 추천. `role`은 `dealer`(공격력으로 싸우는 딜러), `support`, `flex`(딜러·서포터 모두 가능한 캐릭터), `skill`(효과 카드·스킬 피해로 싸우는 스킬 딜러) 중 하나입니다. `core`/`good`/`avoid` 목록과 칩별 이유 `why`를 가집니다. |
| `builds` | 캐릭터 안에서 갈라지는 빌드. 아래 "빌드" 절 참고 |
| `rules` | 조건부 규칙. `when`, `chip`, `verdict`, `why`가 모두 필요하고 `minGrade`는 선택입니다. |
| 목록 항목 | 칩 이름 문자열, 또는 `{ "chip": "이름", "why": "이유", "minGrade": "purple" }` 객체 |

- `characters`에 없는 캐릭터는 포지션을 모르므로 `roles.common`만 적용됩니다.
- 역할별로 받는 공용 목록은 이렇습니다. `dealer`는 `roles.dealer`, `support`는 `roles.support`, `flex`는 둘 다 받습니다. `skill`은 `roles.skill`만 받습니다. 공격력 칩이 효과 카드 피해에 들어가지 않으므로 딜러 공용을 물려받지 않습니다.
- 이유를 쓰지 않으면 `미미 코어`처럼 기본 문구가 나옵니다.
- 이름 하나가 같은 칩의 모든 등급을 가리킵니다. `복싱 글러브 - 초급`처럼 단계까지 쓴 전체 이름은 그 칩만 가리킵니다.

## 판정과 등급

| 판정 | 표시 | `verdict` 값 |
|---|---|---|
| 코어 | ★ 코어 | `core` |
| 무난 | ○ 무난 | `good` |
| 보류 | × 보류 | `avoid` |

해당하는 규칙이 없는 칩에는 배지가 붙지 않습니다.

`minGrade`는 `blue`, `purple`, `orange` 중 하나입니다. 제시된 칩이 이보다 낮은 등급이면 그 규칙은 `보라 이상 권장`이라는 이유의 보류로 바뀝니다.

## 조건

`when`에는 다음 조건을 쓸 수 있습니다.

| 조건 | 의미 |
|---|---|
| `owned` | 내가 이미 가진 칩 |
| `ally` | 나를 뺀 아군 캐릭터 |
| `allyOwned` | 나를 뺀 아군 중 누군가가 가진 칩 |
| `map` | 현재 맵 |
| `character` | 내 캐릭터 |
| `role` | 내 캐릭터의 `role`(`dealer`, `support`, `flex`, `skill`). `roles` 블록과 달리 `flex`를 딜러·서포터에 넣지 않고 그대로 비교합니다 |

### 빌드

한 캐릭터에 코어가 둘 이상으로 갈릴 때 `characters` 항목 안에 `builds`를 적습니다. 캐릭터 `core`는 어느 빌드든 코어인 공용 코어이고, 빌드 `core`는 그 빌드를 고른 사람만 코어로 봅니다.

```jsonc
"소우리": {
  "role": "dealer",
  "core": ["추가 배터리", "바이크 헬멧", "샌드 쿠키"],
  "builds": {
    "A": { "label": "아드 반격", "core": ["아드레날린", "숫돌"], "why": { "숫돌": "체력 절반 이하에서 강해짐" } },
    "B": { "label": "힐 탱커", "core": ["완충 방패", "구급 상자"], "avoid": ["커터칼"] }
  }
}
```

| 키 | 규칙 |
|---|---|
| 빌드 이름 | `A`, `B`, `C`만 쓸 수 있고 둘 이상이어야 합니다. 하나뿐이면 오류를 남기고 `builds` 전체를 무시합니다. |
| `label` | 필수. 화면에 보이는 빌드 이름으로 10자까지, 6자 안팎을 권장합니다. |
| `core` | 필수. 이름을 찾은 칩이 하나 이상 남아야 합니다. |
| `good` / `avoid` | 선택. 형식은 캐릭터 목록과 같고, 그 빌드를 고른 뒤에만 적용됩니다. |
| `why` | 선택. 칩별 이유. 없으면 캐릭터 `why`, 그것도 없으면 `소우리 코어 A` 같은 기본 문구가 나옵니다. |

- 어느 빌드의 `core` 칩이든 하나라도 가지면(등급 무관) 그 빌드를 **고른 것**으로 봅니다. 아무 빌드도 고르지 않았으면 모든 빌드의 코어가 코어입니다.
- 같은 칩을 여러 빌드의 `core`에 적어도 됩니다. 그 칩을 가지면 그 빌드들을 모두 고른 것입니다. 하지만 캐릭터 공용 `core`에 있는 칩은 빌드 `core`에 적을 수 없습니다(오류).
- 고르지 않은 빌드의 코어 칩은 `코어 A를 골라 보류 (B 힐 탱커 빌드 칩)`로 바뀝니다.

서로 다른 조건 종류는 **모두 만족해야** 하고(AND), 한 조건의 목록 안에서는 **하나만 맞으면** 됩니다(OR). 예를 들어 `{ "map": ["워터 타운", "유령 골목"], "owned": ["아드레날린"] }`은 두 맵 중 한 곳이면서 아드레날린을 가졌을 때 적용됩니다.

## 여러 규칙이 겹칠 때

한 칩에 여러 규칙이 걸리면 구체적인 규칙이 이깁니다.

| 단계 | 규칙 종류 |
|---|---|
| 0 | `roles.common` |
| 1 | `roles.dealer`, `roles.support`, `roles.skill` |
| 2 | `characters` 항목 |
| 3 | 조건 1종 `rules` |
| 4 | 조건 2종 `rules` |
| 5 | 조건 3종 `rules` |
| 6 | 조건 4종 `rules` |

같은 단계에서 판정이 엇갈리면 **보류 > 코어 > 무난** 순으로 이깁니다. 단, 단계 3 이상 `rules`의 무난은 `why`가 `주의:`로 시작하지 않으면 더 낮은 단계의 코어를 내리지 않습니다(코어가 이기고 무난은 `참고:`로 붙음). 이기지 못한 규칙의 이유는 툴팁에 `참고:`로 최대 3줄까지 덧붙습니다.

빌드가 있는 캐릭터는 이 판정 뒤에 **닫힌 빌드 덮어쓰기**를 마지막에 적용합니다. 다른 빌드를 골라 닫힌 빌드의 코어 칩은 단계와 무관하게 보류가 됩니다. 단, 빌드 밖 규칙만으로 코어인 칩(캐릭터 공용 코어, 역할 공용 코어, 맵·아군 조건으로 코어가 된 칩)은 덮어쓰지 않습니다.

## 오류 메시지

오류는 BepInEx 로그의 `[규칙]` 줄에 남습니다.

| 메시지 | 뜻 |
|---|---|
| `rules.json N행: JSON 형식 오류 — 이전 규칙을 유지합니다.` | 문법 오류(쉼표, 따옴표, 괄호). N행 근처를 고치세요. 마지막으로 정상이던 규칙이 계속 쓰입니다. |
| `characters.미미.core[1]: '이름' 칩을 찾을 수 없습니다` | 이름 오류. `roles`·`characters`의 목록 항목은 그 항목만 빠지고 나머지는 적용됩니다. `names.json`에 있는 이름과 같은지 확인하세요. |
| `characters.미미: '이름' 캐릭터를 찾을 수 없습니다` | 캐릭터 이름 오류. 이름이 `names.json`에 있는 것과 같은지 확인하세요. |
| `rules[3].when.owned: ...` | 조건 이름 오류. `rules[i]`는 칩 이름이든 `when` 안의 이름이든 하나라도 틀리면 그 조건부 규칙 전체가 빠집니다. |
| `characters.소우리.builds.D: A, B, C 중 하나여야 합니다` | 빌드 이름 오류. 그 빌드만 빠집니다. |
| `characters.소우리.builds: 빌드가 둘 이상 필요합니다` | 쓸 수 있는 빌드가 하나 이하라 `builds` 전체를 무시합니다. |
| `characters.소우리.builds.A.label: ...` | 빌드 이름(`label`)이 없거나 10자를 넘음. 그 빌드가 빠집니다. |
| `characters.소우리.builds.A.core: 칩이 하나 이상 필요합니다` | 빌드 `core`가 없거나 이름을 하나도 찾지 못함. 그 빌드가 빠집니다. |
| `characters.소우리.builds.A.core[0]: '이름'은(는) 공용 코어에 이미 있습니다` | 캐릭터 공용 `core`와 겹치는 칩. 빌드 쪽에서만 빠집니다. |
| `rules[3].verdict`, `rules[3].why` | 조건부 규칙의 필수 값이 없거나 잘못됨 |
| `... 외 N건의 오류가 더 있습니다` | 로그에는 20건까지만 남습니다. 게임 언어와 `names.json`이 맞는지 확인하세요. |

## 수정하고 확인하기

게임을 켠 채로 `rules.json`을 저장하면 몇 초 안에 반영됩니다. 로그에 `규칙 N개를 불러왔습니다(오류 M건)`가 나오면 적용된 것입니다. 이미 열려 있는 칩 선택 창의 배지도 새 규칙으로 바뀝니다.
